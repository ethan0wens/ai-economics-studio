# Expanded pricing catalogue

The initial inventory expansion targets GBP rates in UK South, West Europe and East US 2, plus commercial offers for the UK market. A configuration means one product, SKU or deployment mode at a specified billing region or market. Where a service has separately billed dimensions, the studio can list those as individual resource configurations. One Foundry text deployment can include multiple token meters. A verified configuration has a current rate for each listed component. Partially priced configurations have at least one current rate. Unpriced configurations accept an evidenced manual rate. Unsupported configurations document billing or eligibility that requires reconciliation outside the estimator.

## Maintenance

- Add inventory and evidence in [scope.json](../catalogue/scope.json). For an automatic Azure rate, provide the exact reviewed service, product, SKU, meter, original unit, applicable base-unit conversion and optional ARM SKU or tier starts. A template can cover multiple billing regions. Omit the meter signature for manual input. Set `selectable` to false only where the published billing or eligibility cannot be represented as an independent estimate.
- The [discovery script](../scripts/discovery.ts) scans approved Azure product and SKU groups with bounded same-endpoint pagination. It validates pricing type, currency, region, exact SKU and meter, provider UUID, original unit, current effective date and the full expected tier boundaries. Future, unrelated or ambiguous rows cannot become automatic rates. [Azure Retail Prices API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices/azure-retail-prices)
- The [original mappings](../catalogue/pinned.json) and linked aliases preserve existing scenario and override identities. New configuration/component keys are stable across refreshes and have a separate provider UUID. Review provider UUID changes, unresolved prior rates, tariff changes and large price movements before any replacement can publish.
- Each GitHub Actions refresh generates a content-addressed static snapshot containing the inventory and verified rate records, writes a coverage matrix to the run summary, and runs browser reconciliation checks. The manifest advances only after validation. Cloudflare deployment checks the existing Worker and compares its live HTML, manifest and catalogue against the build. [Operations runbook](12-operations.md)
- Public commercial observations are maintained in [commercial.json](../catalogue/commercial.json). Record the exact UK offer, billed unit, terms, evidence, review date and expiry. Expired commercial rates become unknown. A new rate requires a fresh review of the exact offer.

## Remaining evidence gaps

Regional availability, tenant entitlements, model compatibility, negotiated plans, and billable volumes remain explicitly separate. Advanced OpenAI/reasoning and additional partner variants, batch rates, vision/image/video generation, GPU and fine-tuning workloads, storage replication/retrieval, network routing, shared monitoring allowances, and reservation terms still have manual or unsupported paths. The coverage dashboard lists each scoped configuration and its rate status. It also reports pricing completeness of the open environment independently.
