## State, compatibility and migrations

| State | Ownership and constraints |
| --- | --- |
| Editable environment | Exactly one validated `Environment` or no active workspace. Existing objects, relationship edges, prices, overrides and forecast stay in their current schema. Guided and Advanced write the same state and read the same derived ledger. Actions that create related records validate the complete prospective update before committing. Cancellation preserves previous inputs. Explicit “Create draft” remains available. |
| View state | Keep route, selected object, section, Guided/Advanced mode, active step, optional skip flags, planning intent, inventory filter and return context in memory. A platform intent narrows suggestions. It does not change unrelated objects or overwrite imported choices. Route names, article sections and public offer IDs can be shared. Private object IDs and labels stay out of routes and network requests. |
| Export state | Track editable changes and last offered JSON download separately from which catalogue generated the estimate. Use the same guard before replacing an in-memory workspace. Restore focus when returning to a prior view or cancelling. A new catalogue is still adopted explicitly in an active estimate. Recompute through the same resolver and preserve all user-entered rates. |
| Reports and evidence | Compute ledger, technical findings, licence findings and governance from the active environment and applied catalogue. Readiness uses a view model with stable keys based on object and typed field, line or evidence rule, distinct impact and a target. Group repeated missing inputs while keeping the exact count of unresolved cost lines. Route drafts via the existing missing-field IDs, unknown rates via structured meter and amount fields, evidence via named rules and an explicit fallback destination. Render evidence detail strings without parsing them for control flow. |
| Public content | Examples are static data that produce ordinary environments. Documentation and public rate/evidence assets have independent versions. An example’s description records fictional inputs in human-readable form. The workspace does not feed any generated asset or search index. |
| Imports and export | Keep JSON schema `1.0.0` and existing import validation and legacy version binding. Imports keep persistent IDs, recognised advanced values and unknown pricing state, and recalculate against the applied catalogue. Duplicate and examples generate new IDs and remap linked records and scoped rules. Keep source snapshot semantics. No data migration or browser persistence is required. |

Represent pricing gaps independently from technical risk and from declared governance controls. A rate that becomes unavailable or an evidence relationship that expires uses its existing status. A changed exact offer or unsupported platform connection remains visible with the same edit/review options. A Guided convenience action must call an existing validation path or a schema-checked UI action that uses the same primitives.

## Release test strategy

- **Unit and contract.** Check the view state and route guards, state transitions, trimmed names, exact typed actions for multi-record changes, and a comparison of the validated environment before and after mode changes. Prove shape and valuation equivalence for legacy imports and example copies. Test readiness grouping and targets for missing setup, usage, unknown rate, actual region, unavailable entitlement and optional advisory. Preserve price precedence, capacity and entitlement tests with their independently specified totals.
- **Browser journeys.** Add first visit, welcome usability at 390 px, direct navigation to a workspace-only empty view, Foundry blank to estimate, Copilot with credits, combined, skipped inputs, shared model reuse, rename/resume, safe replacement, invalid/old import, preset opt-in, four example copies and unknown pricing. Check PDF/JSON separately. Run the existing real catalogue checks plus controlled fictional response cases. Never edit expectations to match changed UI-sourced numbers.
- **Trust and accessibility.** Compare UI and PDF amounts, scopes, known/unknown labels and source snapshot. Check no currency conversion or forecast becomes implied. Walk all routes and major forms at 320 CSS px or 200% zoom, and run keyboard, touch and screen reader spot checks. Cover mobile navigation close/return, validation focus, modal cancellation, short help and docs search. Assert only same-origin public asset requests and no workspace storage or identifiers in URLs. Run typecheck, lint, unit tests, pricing/evidence validation and production build before release.
- **Usability validation.** Use a named Foundry task, a Copilot import-and-resume task, and a shared or existing-licence estimate task. Observe whether participants begin without guidance, reach a defensible estimate, distinguish known from complete, explain credits versus tokens and identify where they would save editable work. Record missed actions and wrong interpretations in observable task terms. Review the design if two or more participants hit the same blocking problem. The expert audit provides a baseline, and the later user sessions verify comprehension.

## Risks and responses

| Risk | Response and gate |
| --- | --- |
| Guided steps duplicate profiles, add hidden charges or lose edits. | Define exactly which profile and edges are being created or reused. Preview effects of editing a shared profile. Compare IDs, relationships, quantities and ledger values across both modes. |
| Consolidated numbers imply a complete quote or mix spend scopes. | Keep full counts, scope labels and coverage at summary, detail and export. Test priced, unresolved and zero cases independently. |
| Compatibility and cost remain coupled visually. | Price gaps, evidenced technical conflicts and customer-dependent conditions each retain their independent status. A known amount continues to disclose the caution. |
| Imported advanced values disappear when hidden. | Use one validated environment. Reveal in-context applicable advanced sections and preserve hidden properties during unrelated edits. Round-trip progressively older fixture shapes. |
| Public example IDs and evidence change over time. | A missing or retired offer remains explicit, and the example still opens as a valid draft. Test expired and unavailable evidence. Current verified prices resolve through the same catalogue. |
| Routing makes a local workspace feel persistent. | Keep private data in memory only. On direct reload in a workspace view, show entry and explain reopening via an exported JSON file. Test browser Back and shared documentation routes. |
| Documentation drifts or slows catalogue releases. | Stable article IDs, deterministic generated reference sections, reviewed static prose, link checks and separate read-only external URL checks. Use the existing catalogue validation and refresh as the publication gate for data. |
| Advanced mobile and keyboard regression. | Preserve tested native controls where possible and verify focus on route change, targeted fixes and return. Sidebar, editor and details each have a visible close/back path. |

## Product-owner approvals for Stage 2

1. **Default experience and navigation.** Approve Home and Guided as the initial path, keep Advanced always available and move the duplicate Overview, Architecture and Security & Governance destinations out of primary navigation. The last two remain in contextual views and reports.
2. **Workspace entry and replacement.** Approve one open in-memory environment per tab, explicit name-first creation, Review on import and example opening, and the shared replacement guard with export-first.
3. **Illustrative content.** Approve the four example designs and explicit, editable usage presets. Applicability and current prices are determined at runtime by the existing verified catalogue and evidence policy.
4. **Teaching and release scope.** Approve the Documentation Hub as a primary destination and the inventory in this handoff. Confirm which reviewed user articles ship in the first implementation slice. Recommend Quickstart, pricing and readiness, usage for both platforms, save/reopen, privacy and the four examples before expanding the technical reference.
