# Security risk register

Severity reflects reachability and impact for this browser-only application. Evidence uses synthetic input, mocked services, inspected source and passive public requests.

| ID | Finding and original severity | Reachability and business impact | Verification | Status and residual risk |
| --- | --- | --- | --- | --- |
| S6-01 | Unbounded catalogue and Azure response readers, **Medium** | Oversized provider or static responses can exhaust memory and block planning or refresh. | Inspect original readers. Exercise byte limits and mismatched digests with synthetic streams. | Remediated by bounded reads, structure limits and exact URL/digest checks. Track growth before altering bounds. |
| S6-02 | Unchecked evidence links in inventory and health, **Medium** | Someone able to alter a public asset could place an unreviewed destination behind a trusted link. | Review read and render paths. Assert exact approved HTTPS hosts and reject unsuitable destinations locally. | Remediated. An approved host can still redirect after navigation. |
| S6-03 | Malformed Markdown links could interrupt the reader, **Low** | Invalid committed documentation can affect documentation availability. | Exercise malformed URLs, fragments and raw tags locally. | Remediated. Build validation still checks registered targets and headings. |
| S6-04 | Import shape work and stale asynchronous open decisions, **Medium** | A bounded file could exhaust validation time. An older read could interfere with a newer workspace choice. | Check file/graph limits, reserved keys, replacement/cancellation and sequenced reads locally. | Remediated. Dense valid graphs and PDF reports may be slow on constrained devices. |
| S6-05 | Mutable third-party Actions and overbroad refresh privileges, **High** | Compromised installation or automation increases potential impact on repository content and production. | Check exact revisions against official action repositories, job permissions and credential flow. Validate staged artefacts without credentials. | Remediated in the candidate. Account-level rules remain a separate release gate. |
| S6-06 | Owner controls for repository write access and deploy credentials, **Release blocker** | The account and repository determine who can alter production and approve promotion. | Repository settings queries lacked access. Verify rules, token scope and controlled publisher identity using the operations runbook. | The repository owner confirmed checking the preview publishing controls on 19 November 2026. Reverify them for wider release and after relevant settings changes. |
| S6-07 | Export filename and PDF display controls, **Low** | Unusual names can yield unusable filenames or reorder PDF text. | Test reserved names, PDF metadata, empty annotations and absence of executable action structures. | Remediated. Standard PDF fonts substitute unsupported glyphs. JSON retains the source text. |
| S6-08 | Digests are publisher-controlled, **Informational** | A compromised publisher can change both manifest and content. | Compare public bytes with the recorded digest and review the release transaction. | Scoped delivery controls and owner oversight are separate from byte integrity. |
| S6-09 | Read-only survey tools consume provider responses, **Low** | External data can affect optional investigation or its availability. Survey output does not participate directly in publication. | Inspect triggers, scopes and outputs separately from the production reader. | Keep these jobs read-only and treat output as research pending review. Reassess if a survey becomes a publication input. |
| S6-10 | Public plaintext endpoint can serve the application, **Medium** | Clients without an applicable upgrade policy can receive the application shell over plaintext on first contact. | The public probe compares the HTTP response with the HTTPS bytes. Only HTTP 200 with the exact HTML shell on the existing hostname triggers the exception. | **Open, temporarily accepted for development and preview only.** Custom-domain Cloudflare HTTPS enforcement remains mandatory for wider release. |

## S6-10 preview risk acceptance

On 19 November 2026 the owner accepted S6-10 temporarily for the existing publicly reachable [preview hostname](https://ai-econmics-studio.ethan0wens.workers.dev) pending the custom-domain launch. Prefer HTTPS links as the entry point. Compensating controls include browser HTTPS preload where applicable, a secure-context requirement, HSTS, restrictive CSP, browser-only processing with no customer-data backend, in-memory workspaces and user-directed exports.

Clients without verified upgrade policies can receive the shell over plaintext. The application checks apply to the loaded application. First-contact transport still depends on the edge. Keep S6-10 open until the custom domain and HTTPS enforcement pass `npm run release:public`. See the [issue draft](public-release-blocker.md).

No dependency-advisory exception was accepted. Review residual risks at the next candidate or relevant provider or dependency change.
