# 01 — Product vision, personas and MVP boundaries

## Problem and proposition

Enterprise AI economic planning is fragmented among model inference calculators, Copilot Studio usage estimators, Azure infrastructure calculators, product licensing, governance checks and informal architecture diagrams. AI Economics Studio joins these **without connecting to a tenant**: a user models a hypothetical environment, links objects, estimates costs, understands assumptions and exports a coherent report.

**Primary audiences**: technical product managers, cloud/AI solution architects, Microsoft partners, consultants, FinOps practitioners, IT/CISO stakeholders and community builders. The UI must suit both technical and commercial readers, without requiring users to know cloud SKU identifiers before starting.

**Value proposition**: independent, free, no-account, browser-only, Microsoft-first, credible and source-linked. The model is scenario/planning software, not a service provisioner or official Microsoft quote.

## MVP functional areas (required)

1. **Environment management**: create/rename/delete in memory; explicit JSON save/import, duplicate in memory with remapped IDs and intact relationships; schema versioning; unsaved-work and reload warnings.
2. **Model deployments**: Microsoft provider, region, deployment type/capacity, model identity/version, billing meter, supported agent bindings. Named deployments can be shared by several agents.
3. **Agents**: platform (Foundry Agent Service or Copilot Studio), supported model source (platform-managed or compatible existing Foundry deployment in documented context), tools, autonomy, permissions, linked groups, usage assumptions and referenced resources.
4. **User groups and licensing**: total population, intended audience, active audience, assignments/entitlements, per-agent reach, seats, contract status, net incremental versus already-owned costs.
5. **Usage profiles**: agent executions, calls per execution, tokens per call (input and output), retries, tool calls, upstream/downstream invocations with cycle/overlap safeguards. Explicitly entered or labelled illustrative presets.
6. **TCO ledger**: dynamic monthly/annual, cost category, fixed versus variable, platform/model double-counting safeguards; unknown price propagation; baseline, contract and forecast comparisons.
7. **Compatibility validation**: explain unsupported/unverified platform/model/region/deployment combinations. Incomplete objects can be created in any order.
8. **Pricing catalogue**: versioned public Microsoft retail catalogue, scheduled refreshed curated meters, manual curated licensing, contract overrides and forecast adjustments.
9. **Security/GRC**: advisory recommendations based on agent autonomy, tool/data access, identity, logs, approvals, DLP, retention and governance coverage, with source/evidence and caveats.
10. **Overview, analysis, architecture and report**: dashboards, explainable costs, autogenerated high-level logical diagram, browser PDF.
11. **Open source and trust**: README, CONTRIBUTING, licence, methodology, price source audit, independent disclaimer and basic accessibility.

## Essential user journeys

**A. Blank environment**: user launches empty site, clicks create or import, adds any object in any order. Agent can remain a draft if no compatible model available. Guidance says exactly what is missing. Selected-object inspector edits it; live summary never substitutes £0 for unavailable costs.

**B. Shared model economics**: create two Foundry agents and one compatible Foundry model deployment; both use it. Change model SKU, token rates or usage. Both variable line items update; shared fixed capacity is charged once and allocated only for reporting.

**C. Contract and forecast**: catalogue default → user selects 15% discount for meter X → sets global +20% future retail increase → sees retail baseline, current contract rate and forecasted effective rate, including explicit maths; export/import preserves all rules and provenance.

**D. Microsoft-native Copilot planning**: model a Copilot Studio agent using platform-managed models and its separate licensing/consumption assumptions, never automatically double count Foundry inference. Link a Foundry deployment only for documented, feature-supported integration path; show uncertainty and support rationale.

**E. Report**: generate PDF with the same logical relationships, reconciled ledger, cost categories, incomplete-pricing disclosure and governance gaps as the on-screen UI.

**F. User reload**: without exporting, unsaved environment is lost by design. Import JSON safely restores objects/override rules and recomputes at the current catalogue, explicitly displaying differences versus historical pricing metadata.

## Deferred beyond MVP

- Non-Microsoft providers (AWS Bedrock, Google AI, third-party enterprise suites); design adapters but do not build them.
- User accounts, tenant permissions, actual customer billing integration, automatic Microsoft licence discovery, multi-user collaborative saves, server storage.
- Deployment to Azure, agent runtime telemetry, integrations to customer environments.
- Full scenario library and side-by-side scenario management; basic forecast overlays are in MVP.
- Community template gallery, marketplace, analytics, monetary ROI/business value defaults, AI-generated recommendations requiring paid inference.
- Interactive drag-and-drop architecture authoring; diagram is read-only and derived from inventory.

## Adoption & value analysis (optional sub-feature)

Can be a deferred module or an isolated MVP beta tab if core requirements are fulfilled. Must not delay the core release. Intended audience size, active users and seats are needed for **licence and usage costs**, but an *adoption score/ROI* is optional. Never assume savings, employee pay, business value or minutes saved. Do not score targeted deployments negatively for not engaging an entire organisation.

## Product rules

- Neutral, independent identity with visible source status; no pressure to create accounts or submit a tenant ID.
- Sample environments and test fixture rates are strictly illustrative and must be labelled accordingly. An empty user environment must not contain fabricated real cost estimates.
- Do not sell or imply security compliance; suggest controls with caveats.
