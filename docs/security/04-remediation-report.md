# Security remediation report

- JSON imports retain their schema. The file and structural limits, reserved-property checks and open sequencing protect validation and workspace replacement.
- Evidence links require approved HTTPS endpoints. Technical Markdown renders supported tokens through React. Invalid fragments and destinations remain inert.
- Manifest and catalogue readers bound response bytes and JSON structure. Price snapshot hashes cover the exact bytes. The Azure reader checks the approved endpoint, pagination, redirects, limits and structured records before mapping existing prices.
- Exports use bounded portable filenames and explicit browser downloads. PDF metadata and text filter formatting controls. JSON preserves accepted input and asset URLs are revoked after use.
- The build checks which files and entry resources can be published, expected CSP and selected credential patterns. The promotion checks public HTTPS, CSP, framing, cache policy, MIME type, SPA fallback and catalogue bytes before finalising a release.
- Actions use immutable revisions and locked installations without package lifecycle scripts. Pricing validation reads vendor data in a read-only job. Only publication receives repository write access and production secrets, and only exception reporting receives issue-write permission. The reviewed build and snapshot travel as run-specific artefacts. The guarded publisher verifies the exact revision and uses the existing rollback transaction on failure.
- Dependency monitoring combines npm audit with Dependabot. ESLint checks dynamic code and HTML injection sinks. The risk register tracks owner controls and remaining limits.

See the [risk register](03-risk-register.md) and [verification evidence](05-security-verification.md).
