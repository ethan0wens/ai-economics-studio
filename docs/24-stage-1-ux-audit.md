# Stage 1 · UX audit

**Baseline** · 19 November 2026, application and catalogue at `278cb12`. This is an expert walkthrough of task and interface behaviour. Findings about first-time comprehension are design hypotheses for a later usability study.

## Method

Built and ran the existing production bundle locally with its checked-in validated catalogue. Walked the first visit, created a Foundry assistant from a blank workspace, added Copilot Studio to it, inspected a missing-usage action, tried commercial licensing and Azure AI Search, generated a PDF and attempted an invalid import. Used Chromium at 1440 × 900 and 390 × 844. Inspected the source and the existing browser tests for keyboard, field help, shared charging, JSON round-trips, mismatched compatibility, report reconciliation and catalogue recovery. Direct access to the public Worker was blocked by the audit environment’s network proxy. The browser observations refer to the local build of the published revision. [Published revision](https://github.com/ethan0wens/ai-economics-studio/commit/278cb12) · [Previous hosted production verification](https://github.com/ethan0wens/ai-economics-studio/actions/runs/44521018028)

**Severity** · High delays a core task or can make the estimate misleading. Medium adds meaningful recovery, expert knowledge or navigation burden. Preserve identifies a successful pattern to carry into the redesign.

## Five highest-priority problems

| ID | Severity | Evidence and user impact | Recommended change |
| --- | --- | --- | --- |
| UX-01 | High | First visit opens an Untitled environment in **Overview**. Four metric cards, an empty chart, inventory, comparison and validation precede any named creation flow. There is no Create Environment action. Desktop import begins around y627. At 390 × 844 it begins around y1072. A new user may read “0 incomplete costs” as ready or assume “Add object” creates an environment. [Initial state, heading and overview](../src/app.tsx#L79) · [Overview entry actions](../src/app.tsx#L218) | Replace first visit with a named create/import form. Use Home for resume, examples and local-storage guidance. |
| UX-02 | High | The add dialog offers seven object types at once. On the Foundry path, the link picker contains only **Unlinked** until the user independently creates a deployment. The same happens for a blank Usage profile picker. The walkthrough needed three creations and two links before it could enter the full estimate. This makes internal object boundaries prerequisites for a simple task. [Add dialog](../src/app.tsx#L311) · [Dependency picker](../src/inspector.tsx#L116) | Put create/reuse deployment and usage inline with the agent in Guided. Preserve Advanced inventory and standalone objects. |
| UX-03 | High | The two desktop cost amounts are visible, but the walkthrough saw price comparison at y363, validation at y611, forecast at y934 and the ledger at y1143. In the partial mixed environment, the missing Copilot usage action opened Configuration and focused **Object name** while the needed field was in **Usage**. Users must translate a finding into another navigation step. [Cost page order](../src/app.tsx#L283) · [Validation actions](../src/validation-ui.tsx#L27) · [Inspector setup](../src/inspector.tsx#L33) | Put Estimate readiness immediately below the known total. Each issue should open the precise input or cost detail and provide a way back. Fold technical comparisons and forecasting. |
| UX-04 | High | **Current contract basis** labels the top number even with only retail rates. In the commercial walkthrough, the header showed £1,032.45 known monthly while the proposed environment table showed £5,032.45 because it includes £4,000 declared existing licence spend. The itemised amounts reconciled. The relationship between scopes takes work to establish, and the input for existing spend appears only in Detailed. [Summary basis](../src/app.tsx#L53) · [Existing spend control](../src/inspector.tsx#L179) · [Estate table](../src/validation-ui.tsx#L52) | Lead with known modelled costs and an explicit scope. Show new and existing costs together with a concise scope explanation and detail link when applicable. |
| UX-05 | High | Seven peer destinations mix the task flow with technical reviews. The brand leads back to Overview and the button-based route state gives browser Back and shared links no page meaning. Import disappears from Overview when objects exist. Rename is inside a clickable breadcrumb and reset/duplicate live under Reports. On mobile the navigation remained expanded after Escape. These choices make resuming, recovering, learning and navigating harder. [Navigation and view state](../src/app.tsx#L19) · [Workspace actions](../src/app.tsx#L292) · [Mobile navigation](../src/styles.css#L130) | Provide a link-based five-destination navigation and secondary catalogue, consistent workspace actions, public documentation deep links and predictable mobile dismissal. |

## Detailed findings by task

| Area | Severity | Observation, consequence and direction |
| --- | --- | --- |
| Environment lifecycle | Medium | The tab already protects unexported changes on reload and during replacement, and executes import validation before replacing. The green “In memory” label does not distinguish a newly blank session, successful export or restored file. Invalid JSON can show raw schema names such as `schemaVersion` and `createdAt`. Give a visible export state and a short recovery message with details. [Session and import code](../src/app.tsx#L101) · [Reports entry](../src/app.tsx#L292) |
| Builder and configuration | Medium | Inventory badges, inspector sections and three disclosure levels are useful for repeated edits. First-time users must work out both which section and which detail level contain an input. The model control opened with 70 options including Custom/Unlisted at this snapshot. Essential shows the retail picker, model identifier and billing mode side by side in the task flow, even for an exact selected offer. Editing identifier fields can clear that selection. Use searchable natural-language offers, then reveal editable identifiers and state the effect of changes. [Model picker and selection](../src/inspector.tsx#L55) · [Disclosure mechanics](../src/inspector.tsx#L228) |
| Foundry validation | High | Billing configuration identifies a rate. Actual deployment region and model/capability assumptions are separate and currently entered under Detailed. The simple walkthrough produced priced input and output and separate unverified/conditional technical evidence. Users need both facts in one view, with an action for geography when the estimate relies on it. [Deployment inputs](../src/inspector.tsx#L160) · [Technical checks](../src/compatibility.ts) |
| Copilot Studio | High | One available model-source option still needs to be chosen before Usage appears. The first numeric field asks for billable monthly credits and an allowance control appears before the user understands credit basis. The tool correctly has a separate usage model. Explain credits before inputs, expose the total on selecting the platform, and keep activity/allowances/packs and external prompts as conditional detail. [Agent configuration](../src/inspector.tsx#L136) · [Agent usage](../src/inspector.tsx#L260) |
| Usage comprehension | Medium | Foundry inputs are split between the agent’s Usage tab and a standalone profile’s Configuration. The profile help explains monthly runs, requests and per-call tokens, but configuring and linking are separate tasks. There is no example or opt-in preset in that path. Keep the distinction between input and output, separate workloads, cached input and retries. Offer inline editing and a small worked example. [Usage profile form](../src/inspector.tsx#L215) · [Agent usage and profile links](../src/inspector.tsx#L260) |
| Licensing, prerequisites and groups | High | The product picker and prompts support owned, new and unknown procurement. Selecting the base and add-on as standalone items produced priced new seats alongside conditional assignment evidence in the browser. The relationship editor asks about type, target, assigned and replaced seats separately. Explain distinct seats and prerequisite confirmation in the licence flow. Keep edge scope and replacement dates in the expanded editor. [Licence fields](../src/inspector.tsx#L179) · [Connection editor](../src/inspector.tsx#L330) · [Licence validation](../src/entitlements.ts) |
| Supporting resources | Medium | A catalogue offer or exact manual meter can be selected. On Azure AI Search the quantity hint observed was “Enter base units per month. The selected meter bills per 1 Hour (1 base units).” The input leaves a first-time user to work out search-unit-hours. Show the product’s actual unit beside the field and explain how to derive it. [Supporting resource configuration](../src/inspector.tsx#L190) |
| Agreements, forecast and cost detail | Medium | Exact meter evidence, quantities, sources, discount and contract interactions are available once expanding a line. The forecast panel is visible before core drivers or the ledger even when forecast is unused. Move opt-in agreement and forecast controls behind the relevant scope, with clear active summaries. [Line details and forecast](../src/pricing-ui.tsx#L97) |
| Architecture | Preserve / Medium | The logical graph, keyboard nodes, SVG and tabular alternative are useful for explaining shared dependencies. A standalone destination before the user has objects shows an empty diagram without a direct task action. Give Builder and Reports contextual access. Keep the graph declarative and offer its list first on mobile. [Logical diagram](../src/diagram.tsx#L8) |
| Security & Governance | Medium | A small mixed example produced ten findings, with repeated unknown controls across agents. The current assessment explains the declared model and links sources, but many prompts appear before users can estimate a workload. Keep findings and policy editing in Advanced and report material. Prioritise input issues that affect price in readiness. [Advisory list](../src/app.tsx#L288) |
| Pricing Catalogue | Medium | Coverage and health are strong evidence assets. The page also repeats current environment completeness after the public reference coverage, and distinguishes rates and configurations only after reading. Make it a secondary reference, keep coverage distinct from the open estimate, and target the exact relevant public offer where possible. [Coverage UI](../src/coverage-ui.tsx) · [Catalogue Health](../src/catalogue-health-ui.tsx) |
| Reports and export | Preserve / Medium | The browser generated a real PDF. The existing suite checks that totals and the logical diagram reconcile, and JSON can restore edits. The page labels and top-level actions repeat export while sharing a screen with reset. Report and editable-file purposes need distinct actions. Put the estimate scope, partial warning and next action before export. [Export actions](../src/app.tsx#L149) · [Report generation](../src/report.ts) |
| Mobile reflow | High | The tested screens had zero document-width overflow. At 390 × 844, desktop-order stacking put Inventory at y530 and the new-agent editor heading at y821 when positioned at the top of Builder. On a full inventory this pushes editing farther down. Give selected objects a single-column editor view with explicit Back and a focus target. [Builder structure](../src/app.tsx#L256) · [Responsive styles](../src/styles.css#L130) |
| Accessibility | Medium | Short keyboard and automated checks found strengths in existing field help, skip link, dialog and graph controls. Mobile Escape did not close navigation. Catalogue axe checks flagged two links in prose for distinction. Explore underlines and visible focus, navigation restoration and labelled scrolling regions. A bounded automated check saw no findings on the tested Overview, Cost Analysis and Architecture states. These observations do not establish full WCAG conformance. [Navigation control](../src/app.tsx#L198) · [Field help](../src/fields.tsx#L5) · [Existing accessibility checks](../tests/e2e/studio.spec.ts#L101) |
| In-product guidance | Medium | Typed help covers required/optional status, units and sources, and works with pointer, focus and touch. Required concepts often still appear only after entering an object or opening help. Users have no in-product article index, search or stable context links. Preserve short field help and move explanations of prerequisite concepts into step copy and the Documentation Hub. [Help registry](../src/field-help.ts) · [Repository field guide](13-field-guide.md) |

## Preserve and verify

Keep exact catalogue lookups, authored override decisions, independently verified compatibility and licensing, any-order model operations, a single ledger, explicit partial totals, browser PDF and deliberate JSON import/export. Preserve the independence and privacy text. The exploratory interactions requested only the preview origin, and local and session storage were empty in the checked tab. The existing regression suite provides the fuller result checks.

Baseline verification passed the production build, pricing and evidence validation, typecheck, lint, 61 unit tests and 18 local Chromium tests with the published catalogue checks enabled. The four proposed examples also passed a schema and ledger probe against the pinned catalogue. The existing-licence example found the declared qualifying group, and the shared model produced one charge with the expected 75/25 attribution. The redesign acceptance cases are specified separately.
